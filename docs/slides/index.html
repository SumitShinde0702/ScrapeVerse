About the project

A package.json becomes live maintainer-page intelligence.

package.json→ URLs→ Bright Data→ Zod→ tags + bumps
  • Input — paste or upload a manifest
  • Action — scrape npm + GitHub Releases HTML
  • Output — security / deprecation / breaking / yanked
  • Survival — Self-Healing on the same collector id

We do not invent CVEs. We do not replace NVD. We surface the prose maintainers already published — earlier — and we refuse to store empty fields that look like a healthy scrape.

Learning and growth

What building this taught me

  • Failure is a runtime signal — not a Jira ticket for next sprint.
  • Schema-first scraping — Zod is the product, not a nicety.
  • Heal in place — spawning a new collector hides the problem.
  • One orchestrator, two clients — if an agent can't consume it, the UI was lying.
  • The window is before the CVE — not a bigger pile of CVE ids.

Learning · next

If this kept going

  • PyPI / crates / Maven maintainer pages
  • Durable findings store — not in-memory
  • Better GitHub repo resolution from npm
  • Heal evals: break fixtures on a schedule
  • Watch as a real always-on service
  • Keep tags deterministic — no mystery scores
